# 股票复盘 Agent 系统需求分析

## 1. 文档目的

本文定义一个面向中国 A 股市场的「收盘复盘与次日交易候选决策支持 Agent 系统」的产品与技术需求。系统在每个交易日收盘后自动汇集市场、板块、个股、公告及新闻等信息，通过可追溯的多 Agent 协作和大模型归纳，形成结构化复盘报告，并输出次日可关注的股票候选池与风险提示。

系统定位为研究和决策支持工具，不构成投资建议，不直接连接券商账户或自动下单。所有候选结果均须由用户结合自身风险承受能力独立判断。

## 2. 目标与边界

### 2.1 核心目标

1. 在交易日收盘后稳定完成市场全景复盘，解释指数、情绪、资金、热点与事件之间的关联。
2. 基于明确、可配置、可回测的规则与模型，生成次日分层候选股，而非仅输出不可验证的自然语言观点。
3. 为每条关键结论保留数据来源、计算时间、指标值及推理依据，支持人工核验。
4. 累积历史报告、候选池与实际表现，评估策略有效性并持续优化。

### 2.2 MVP 范围

- 支持沪深 A 股普通股票；首期可排除北交所、ST、退市整理、上市未满指定天数及长期停牌股票。
- 每个交易日 15:10（可配置）启动；在 16:00 前产出报告和候选池。
- 提供 Web 页面和 Markdown/PDF 导出；支持查看历史报告与候选池表现。
- 支持日线、分钟线、成交、资金流、涨跌停、行业/概念、公告与新闻数据。
- 输出观察、低风险关注、重点跟踪三个层级的候选标的及风险说明；不输出“保证收益”或确定性买卖指令。

### 2.3 非范围（首期）

- 自动交易、实盘代客操作、收益承诺。
- 覆盖港股、美股、期货、期权、基金等多市场品种。
- 盘中高频决策与毫秒级行情处理。
- 以大模型替代行情计算、因子计算和风控规则。

## 3. 用户与使用场景

| 用户角色 | 主要诉求 | 核心操作 |
| --- | --- | --- |
| 个人投资者 | 快速理解当日市场及次日关注方向 | 阅读报告、筛选候选股、查看证据与历史表现 |
| 投研人员 | 提升复盘效率并保留研究过程 | 配置策略、审阅 Agent 结论、导出报告 |
| 管理员 | 保证数据、任务和模型稳定 | 配置数据源、模型、日历、权限与告警 |

典型流程：交易日收盘后，系统确认行情落库并校验完整性；各专职 Agent 并行分析；综合 Agent 汇总冲突观点并生成报告；选股与风控模块输出候选池；用户次日开盘前查看候选理由、触发条件和失效条件；收盘后系统回写候选表现并用于评估。

## 4. 业务需求

### 4.1 交易日与任务编排

1. 根据中国交易所日历判断交易日，非交易日不执行正式复盘。
2. 收盘任务需具备“等待数据就绪、重试、补跑、幂等”能力；同一交易日同一版本只产生一份正式报告。
3. 任务状态至少包括：待执行、数据校验中、分析中、待人工审核、已发布、失败、已补跑。
4. 数据缺失、模型调用失败或关键指标异常时，报告必须标明降级状态，不得伪造结论。

### 4.2 数据需求

| 数据域 | 最低字段/内容 | 用途 |
| --- | --- | --- |
| 市场行情 | OHLCV、成交额、换手率、涨跌幅、复权因子 | 指数与个股走势、技术指标、流动性分析 |
| 市场宽度 | 上涨/下跌家数、涨停/跌停、连板、炸板、封板率 | 市场情绪与赚钱效应 |
| 资金与估值 | 北向/主力资金（数据源允许时）、两融、行业估值 | 资金偏好及拥挤度判断 |
| 分类数据 | 申万行业、概念、指数成分、地域等 | 板块轮动和归因 |
| 事件文本 | 公司公告、监管信息、财经新闻、宏观政策 | 事件驱动与风险识别 |
| 基础资料 | 股票简称、上市日期、ST 状态、停复牌状态 | 标的过滤与展示 |

数据源应支持多供应商适配，记录供应商、采集时间、原始标识和许可状态。行情计算以结构化数据为准；新闻与公告仅作为解释、事件标签和风险补充，必须注明来源与发布时间。

### 4.3 多 Agent 分工

| Agent | 输入 | 输出 | 约束 |
| --- | --- | --- | --- |
| 市场全景 Agent | 指数、宽度、成交、资金 | 市场阶段、风险偏好、核心数据摘要 | 引用所有关键数值 |
| 情绪与短线 Agent | 涨停生态、连板、炸板、异动 | 情绪周期、题材强弱、短线风险 | 不能把相关性表述为因果 |
| 板块轮动 Agent | 行业/概念涨幅、资金、领涨股 | 强势/分化/潜伏板块及证据 | 分类口径须固定且版本化 |
| 个股研究 Agent | 技术面、基本面、事件、风险标签 | 个股催化、形态、风险及候选评分 | 禁止编造公告或财务数据 |
| 新闻公告 Agent | 新闻、公告、政策文本 | 事件摘要、影响对象、可信度 | 去重、时效判断、来源溯引 |
| 选股与风控 Agent | 因子结果、上述 Agent 结构化输出 | 候选名单、触发/失效条件、仓位建议区间 | 强制执行硬性过滤规则 |
| 报告主编 Agent | 所有结构化结论与证据 | 一致、可读、带不确定性的最终报告 | 只做归纳，不重新臆测数据 |

Agent 之间使用 JSON Schema 传递结构化结果。大模型负责总结、归因假设、冲突识别和报告写作；指标计算、排序、阈值判断、过滤和回测由确定性服务完成。

### 4.4 候选股生成与风控

候选池采用“硬过滤 + 多因子评分 + 风险调整 + 人工可审阅”的方式。

硬过滤（初始建议，可配置）：ST/退市整理/停牌股票；上市时间不足 60 个交易日；近 20 日日均成交额低于阈值；涨跌停状态不满足策略要求；存在重大风险公告或数据缺失；不符合用户设定的行业、价格、流动性限制。

评分维度建议：趋势与动量、量价配合、相对强度、行业强度、资金/成交确认、事件催化、估值与基本面质量、波动和回撤风险。每个维度归一化为 0–100 分，权重按策略版本保存。最终得分须附带因子贡献明细，避免“黑箱推荐”。

每个候选标的至少给出：代码和名称、所属板块、候选层级、综合分及排名、入选理由、关键证据、次日关注条件、失效条件、风险标签、建议观察期限和数据截至时间。建议采用条件化表达，例如“仅在放量突破指定价位且板块维持强势时关注”，不把系统输出包装为确定收益承诺。

### 4.5 后续投资选股推荐功能

该功能将“日终候选池”升级为可持续管理的研究推荐：从发现机会、生成观察名单、满足条件后进入推荐，到跟踪、失效、复盘全程留痕。首期仍仅提供研究辅助与条件化建议，**不接入自动下单、不承诺收益，也不应以无条件的“买入/卖出”措辞替代风险披露**。

#### 4.5.1 用户画像与推荐偏好

系统须允许用户建立一个或多个“投资画像”，推荐结果必须关联画像版本，避免以单一策略服务所有风险偏好。画像至少包括：

| 配置项 | 示例/说明 |
| --- | --- |
| 投资风格 | 短线趋势、波段成长、价值低估、事件驱动；首期建议提供预设模板 |
| 持有周期 | 隔日、3–5 个交易日、2–4 周、1–3 个月 |
| 风险等级 | 保守、平衡、进取；决定最大波动、集中度与行业暴露约束 |
| 资金规模与单票上限 | 用于模拟仓位区间，不应获取或操作真实账户权限 |
| 股票范围 | 全 A、指定指数成分、自选行业、排除名单 |
| 约束条件 | 是否排除创业板/科创板、ST、低流动性、高波动、特定行业 |
| 参考基准 | 沪深 300、中证 500、创业板指或自定义指数 |

当用户未完成画像配置时，系统只能展示通用观察名单，不得标为个性化推荐。任何配置修改均产生新画像版本，并从下一次推荐任务生效。

#### 4.5.2 推荐策略与策略组合

策略由可配置的“股票池 + 入场条件 + 排序因子 + 风险约束 + 退出/失效条件”组成。建议首期提供以下策略模板，并允许管理员复制后调参：

| 策略模板 | 适用市场状态 | 核心入选逻辑 | 典型失效条件 |
| --- | --- | --- | --- |
| 强势趋势跟随 | 指数趋势向上、主线清晰 | 个股相对强度高、放量突破、板块强势 | 跌破趋势线/关键均线、板块转弱 |
| 板块轮动 | 市场分化、热点切换 | 板块资金改善、龙头确认、补涨空间合理 | 板块持续流出、核心标的走弱 |
| 事件催化 | 可验证的公告/政策催化 | 事件有效、受益链条明确、流动性达标 | 事件被证伪、利好兑现、监管风险 |
| 低波动质量 | 震荡或风险偏好偏低 | 基本面质量、低波动、估值安全边际 | 基本面恶化、估值显著透支 |

系统可基于市场状态路由到一个或多个策略，但策略组合须设置最大重叠率、最大行业暴露和最大单一主题暴露。若当前市场状态不满足任一策略的适用前提，应输出“空仓/仅观察”状态；空结果是正常且应被保留的决策结果。

#### 4.5.3 推荐生命周期与状态机

每一条推荐记录应有唯一 ID，并可按下列状态流转：

```text
发现（扫描命中） → 观察（等待触发） → 可关注（条件满足） → 跟踪中
       │                    │                  │                 │
       └──── 淘汰/过期 ◄─────┴──── 失效/风控退出 ◄─────────────────┘
                                                       │
                                                    已复盘
```

- 发现：通过策略初筛，尚未达到用户画像或触发条件。
- 观察：展示关键价格/成交量/板块条件，设置有效期与提醒。
- 可关注：在数据确认后满足策略条件，给出风险预算范围与条件化关注说明。
- 跟踪中：每日更新表现、事件、风险和原始假设是否仍成立。
- 失效/风控退出：命中止损、时间止损、基本面/事件反转、策略失效或组合约束。
- 已复盘：达到评估期限或终止后沉淀结果、归因及是否需要调整策略。

状态变化必须由规则引擎或经审核的人工操作触发，并记录前后状态、触发指标、操作人/Agent、时间和策略版本；大模型不可绕过状态机直接修改状态。

#### 4.5.4 推荐卡片和详情页

推荐列表默认按“与画像匹配度、置信区间、风险调整后分数、流动性”排序，不单以预期收益排序。每个推荐卡片应显示代码、名称、当前状态、策略名称、推荐日期、有效期、综合评分、风险等级、行业/主题、关键触发条件、风险标签和数据截至时间。

详情页必须包括：

1. 推荐逻辑：入选的规则、因子贡献、与同策略标的的相对排名。
2. 证据面板：行情指标、公告/新闻原文链接、板块数据和数据时间戳。
3. 交易计划模板：关注区间、确认信号、失效阈值、时间止损、建议最大风险预算；区间/阈值必须标识计算口径。
4. 风险面板：波动、回撤、流动性、涨跌停、财务、事件、行业拥挤和数据质量风险。
5. 跟踪时间线：状态变更、价格表现、后续公告、系统提醒与用户备注。
6. 历史相似案例：仅展示经时间一致性处理的历史样本，注明样本数和局限性。

#### 4.5.5 组合层风险控制

即使单只股票满足条件，组合层也必须再次校验。可配置约束包括：单标的最大建议风险预算、单行业/主题最大暴露、最大持仓数、候选关联度上限、组合预估波动、最大回撤预警线、当日新增推荐数量、连续亏损后的冷却期。

对于“风险预算/仓位区间”，系统应采用透明计算：以用户可投入研究资金、单笔最大可承受亏损比例和入场至失效阈值的距离为输入，输出示例区间及假设条件。若缺少必要输入，只展示风险等级与不超过用户上限的占位提示。不得输出暗示必然成交或适合所有人的具体仓位结论。

#### 4.5.6 持续跟踪、提醒与人工反馈

1. 每日收盘后更新所有活跃推荐；盘中能力作为后续版本，首期不以盘中实时触发为依赖。
2. 支持提醒：进入可关注状态、接近/触发失效条件、有效期届满、出现重大公告、板块风险升级、组合暴露超限。
3. 用户可标记“已关注、忽略、加入自选、关闭”，并填写原因；这只影响个性化排序与研究反馈，不得被直接视为真实成交。
4. 人工投研人员可以审核、冻结、撤回推荐，并说明原因；已发布版本不可静默篡改。
5. 推荐终止后自动生成简短复盘，包括实际路径、是否满足初始条件、风险控制是否生效及改进标签。

#### 4.5.7 推荐输出接口

推荐服务应提供 Web 查询和结构化 API。核心字段：`recommendation_id`、`profile_version`、`strategy_version`、`symbol`、`state`、`score`、`score_breakdown`、`confidence`、`valid_from`、`expires_at`、`entry_conditions`、`invalidation_conditions`、`risk_budget_assumptions`、`evidence_refs`、`risk_flags`、`generated_at`。API 响应必须返回数据新鲜度、模型版本和免责声明标识。

### 4.6 复盘报告内容

正式报告须包含以下章节：

1. 执行摘要：市场一句话结论、风险级别、次日关注主线。
2. 指数与成交：主要指数涨跌、成交额、市场宽度、与近 5/20 日对比。
3. 情绪复盘：涨跌停、连板高度、炸板率、赚钱效应、情绪阶段判断。
4. 板块复盘：强势、分化、走弱板块；领涨标的、资金和事件证据。
5. 重要事件：宏观、行业、公司公告及可能影响，区分事实与推断。
6. 候选池：分层展示候选股票、理由、触发条件和风险。
7. 次日情景预案：强/中/弱三种市场情景下的观察重点及纪律。
8. 风险提示与数据质量：缺失数据、冲突观点、模型版本和免责声明。

## 5. 功能需求

| 编号 | 功能 | 验收要点 |
| --- | --- | --- |
| FR-01 | 数据采集与校验 | 可按交易日采集；缺字段、重复、异常价格可检测并告警 |
| FR-02 | 指标计算 | 指标公式、参数、输入版本可查询；结果可重复计算 |
| FR-03 | Agent 编排 | 支持并行、依赖、超时、重试和单 Agent 降级 |
| FR-04 | 报告生成 | 可生成 HTML/Markdown，包含必填章节与证据引用 |
| FR-05 | 候选池 | 可配置过滤/权重/数量；每项有评分与风险理由 |
| FR-06 | 策略管理 | 策略、Prompt、模型、阈值与数据口径均需版本化 |
| FR-07 | 人工审核 | 支持编辑摘要、剔除候选、添加备注后发布 |
| FR-08 | 历史评估 | 统计 T+1、T+5 表现、胜率、最大回撤和基准超额 |
| FR-09 | 检索与追溯 | 可按日期、股票、板块检索，并定位至原始证据 |
| FR-10 | 告警通知 | 任务失败、数据异常、报告发布可通过可配置渠道通知 |
| FR-11 | 投资画像 | 支持风险、周期、范围、约束等配置，并保留版本 |
| FR-12 | 推荐策略编排 | 支持策略模板、市场状态路由、组合与空结果输出 |
| FR-13 | 推荐生命周期 | 支持发现、观察、可关注、跟踪、失效、复盘及审计 |
| FR-14 | 组合风险控制 | 在个股推荐前校验行业、主题、持仓数、风险预算等限制 |
| FR-15 | 持续跟踪与提醒 | 每日更新活跃推荐，并在风险、事件、到期时通知 |
| FR-16 | 用户反馈 | 支持忽略/关注/备注；反馈可用于排序评估但不等同成交 |

## 6. 非功能需求

- 性能：在行情与文本数据完整时，覆盖全市场的日终任务应在 50 分钟内完成；报告页面首屏加载目标小于 3 秒。
- 可用性：任务可重试，关键数据和正式报告需持久化；单一大模型或新闻源故障可降级。
- 可解释性：每个候选的评分、过滤原因、主要证据和策略版本可查询。
- 安全：数据源密钥仅保存于密钥管理服务；按角色控制策略修改和报告发布；保留审计日志。
- 合规：展示数据版权来源与许可限制；明确“仅供研究参考”；禁止收益保证和诱导性表述。
- 可观测性：记录任务耗时、数据新鲜度、模型调用量/成本、失败原因、输出质量评分。

## 9. 质量评估与验收

### 9.1 输出质量

- 数值一致性：报告关键行情数字与数据仓库一致率 100%。
- 可追溯性：候选标的和重要事件的证据覆盖率不低于 95%。
- 幻觉防控：模型不得生成未在输入证据中出现的具体价格、公告或财务数字；自动规则检测并拦截。
- 可读性：每日报告含必填章节，结论和风险可在摘要页快速读取。

### 9.2 策略评估

不能仅以短期收益判断 Agent 成功。至少按策略版本、市场状态、行业和候选层级拆分统计：T+1/T+5 收益、相对基准超额收益、胜率、盈亏比、最大回撤、换手率、命中率与覆盖率。回测必须避免未来函数，使用当时可获得的数据，并计入涨跌停、停牌、滑点、手续费和流动性约束。

### 9.3 MVP 验收场景

1. 对一个历史交易日补跑，可稳定得到同一策略版本下相同的结构化候选结果和推荐状态。
2. 任意候选可查看因子分、过滤记录、事件来源和生成版本。
3. 数据源缺失时，系统暂停发布或发布带醒目降级标识的报告。
4. 管理员调整权重后，生成新的策略版本，不覆盖历史结果。
5. 历史候选池可展示与沪深 300（可配置）相比的表现。
6. 当用户画像为保守且某候选导致行业暴露超限时，系统必须拦截或降级该候选，并展示拦截依据。
7. 推荐进入失效状态后，详情页能展示命中的规则、当时数据快照及完整状态时间线。

## 11. 待确认事项

1. 首期市场范围是否仅限 A 股，以及是否纳入北交所、科创板和创业板。
2. 可使用的数据供应商、预算、授权范围及延迟要求。
3. 用户的交易风格（短线趋势、波段、价值等）及持仓周期；这决定候选评分和评估周期。
4. 报告的接收渠道（Web、邮件、企业微信、飞书等）和是否需要人工审核后发布。
5. 是否需要接入自有持仓、交易记录或自选股；此项涉及更高的数据安全和合规要求。

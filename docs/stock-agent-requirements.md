# 股票复盘与选股 Agent 需求文档

> 文档状态：V1.0（需求基线）  
> 目标市场：首期默认中国 A 股  
> 产品定位：投研与决策支持工具，不构成投资建议，不在首期自动执行交易

## 1. 背景与目标

用户需要一个在每个交易日收盘后自动运行的股票 Agent。系统应汇总当日市场、行业、主题和个股表现，结合行情、基本面、资金面、新闻事件与风险指标形成结构化复盘；随后基于可配置策略筛选下一交易日值得关注的股票，提供评分、入选依据、风险点和观察条件。

### 1.1 产品目标

- 将人工收集数据、归纳行情和初筛股票的流程自动化。
- 在固定时间生成口径一致、证据可追溯的收盘复盘报告。
- 输出有限、可解释、经过风险过滤的次日候选股票池。
- 保存每次推荐与当时数据快照，支持事后验证、回测和策略迭代。
- 明确数据时点，杜绝未来函数、幸存者偏差和不可复现结论。

### 1.2 非目标

- V1 不自动下单，不直接连接实盘交易账户。
- 不承诺收益率或预测确定性，不使用“必涨”“稳赚”等表述。
- 不用大模型直接臆测价格；大模型主要负责信息归纳、解释和报告生成。
- 不替代持牌投资顾问，也不生成针对个人财务状况的确定性投资建议。

## 2. 用户与典型场景

### 2.1 目标用户

- 个人投资者：希望快速了解市场并获得次日观察清单。
- 策略研究者：希望配置选股因子、验证效果并追踪信号。
- 投研团队：希望统一复盘口径、沉淀历史报告和决策证据。

### 2.2 核心使用流程

1. 交易日收盘后，调度器确认当日行情数据已完整落库。
2. 系统执行数据质检，并标记停牌、涨跌停、退市风险、异常成交等状态。
3. 市场复盘模块分析指数、广度、成交、风格、行业、主题、资金和事件。
4. 选股引擎按策略生成股票候选集，经过可交易性及风险过滤后评分排序。
5. Agent 生成带数据来源、数据时间和置信度的报告。
6. 用户查看报告、筛选候选股、阅读入选/排除原因并添加自选或反馈。
7. 下一交易日收盘后，系统更新候选股表现及策略统计。

## 3. 范围与关键假设

- 首期覆盖沪深 A 股；指数、ETF、港股和美股作为后续扩展。
- 运行日历使用交易所交易日历，不按自然日盲目运行。
- 默认在收盘数据稳定后执行，例如 16:30；时间可配置并支持失败重试。
- 默认分析周期包括 1、5、20、60 个交易日。
- 候选结果是“次日观察池”，不是买入指令。
- 所有信号只使用选股时点前已公开且可获得的数据。
- 复权口径、财务报告可见时间、行业分类版本必须固定并记录。

## 4. 功能需求

### 4.1 数据接入与治理

#### 4.1.1 必需数据

- 行情：日线 OHLC、前收盘价、成交量、成交额、换手率、振幅、复权因子。
- 证券主数据：代码、名称、上市日期、交易状态、ST/退市风险、所属市场。
- 指数与行业：主要宽基指数、行业指数、成分股及行业分类。
- 基本面：财务报表、估值指标、盈利能力、成长性、现金流、负债水平。
- 公司行为：分红、送转、增发、回购、解禁、停复牌和除权除息。
- 信息事件：公告、业绩预告、新闻、监管事件；保留发布时间与来源链接。

#### 4.1.2 可选增强数据

- 主力/北向等资金数据（以数据源实际可用性和合规性为准）。
- 龙虎榜、融资融券、股东变化、机构调研和一致预期。
- 宏观指标、商品、汇率、海外指数等跨市场变量。

#### 4.1.3 数据质量

- 检查数据是否齐全、时间戳是否正确、股票池数量是否异常。
- 检测重复记录、缺失值、极端值、复权跳变与跨源数据冲突。
- 数据未就绪时不得静默生成完整报告；应降级、标注缺失项或中止任务。
- 每次任务保存数据版本、来源、拉取时间、覆盖率和质检结果。

#### 4.1.4 每日数据落盘与快照

- 每个交易日必须将数据持久化落盘，不能只保存在进程内存、模型上下文或临时缓存中。
- 落盘范围包括原始行情、证券主数据、复权因子、基本面、公司行为、指数与行业、公告新闻、清洗后数据、特征、市场状态、各 Agent 结构化结果、候选池、风控结论、报告和效果评估。
- 数据按 `market/trade_date/data_type` 进行逻辑分区；股票级记录同时以证券代码作为检索键。
- 原始层保存数据源返回内容或等价无损副本，只追加不覆盖；标准层和特征层允许重算，但必须保留版本及与原始快照的关联。
- 每次运行生成唯一 `run_id` 和 `data_snapshot_id`，记录交易日、数据截止时间、来源版本、复权口径、行业分类版本、记录数、文件清单和校验和。
- 同一交易日可能多次补数或重跑，每次均创建新快照；通过 `is_current` 或发布状态标识当前有效版本，不覆盖旧快照。
- 支持按照交易日、股票代码、数据类型、策略版本和运行实例查询历史数据。
- 任意历史报告和候选结果必须能定位到当时使用的不可变数据快照，不能默认读取最新数据进行解释。
- 文件型数据建议采用 Parquet 等列式格式，对象存储或文件系统保存大体量数据；关系型数据库保存元数据、索引、任务状态和决策链。具体技术选型可按部署环境调整。

#### 4.1.5 写入一致性与完整性

- 每类数据先写入暂存区，完成记录数、Schema、业务日期和校验和检查后再原子发布，避免读取到半成品。
- 使用交易日、市场、数据类型、来源和版本组成幂等键，重复执行不得产生无法识别的重复记录。
- 数据清单（manifest）应标记各数据集为等待、写入中、已校验、已发布、降级或失败。
- 核心数据全部发布后才允许启动选股；非核心数据缺失时按降级策略执行并记录缺口。
- 跨表数据应保证业务日期和快照一致，防止行情使用当日数据而行业成分或基本面误用其他时点版本。
- 落盘失败时任务必须失败或降级并告警，不得在没有持久化证据的情况下发布正式报告。

#### 4.1.6 数据保留、备份与恢复

- 原始数据、策略输入快照、候选结果、风控记录和审计日志默认长期保存；具体期限由数据许可、合规要求和存储成本确定。
- 临时文件、中间缓存与可从固定输入确定性重建的数据可设置较短保留期，但删除前必须确认不存在历史结果引用。
- 每日增量备份，定期执行全量备份和恢复演练；备份副本与生产存储故障域隔离。
- 建议恢复点目标 RPO 不超过 24 小时，恢复时间目标 RTO 不超过 4 小时，最终指标按部署等级确认。
- 数据归档、压缩、迁移和删除必须保留操作审计；涉及用户持仓和偏好的数据支持按规则导出及删除。
- 系统应提供按 `data_snapshot_id` 重建特征、重跑策略和重新生成报告的能力，并校验重放结果。

### 4.2 收盘复盘

#### 4.2.1 市场概览

- 展示主要指数收盘点位、涨跌幅、成交额及多周期表现。
- 对比当日与 5/20 日均成交额，判断放量或缩量。
- 统计上涨、下跌、平盘家数，涨停、跌停、炸板及连板情况。
- 统计市场中位数收益、创新高/新低股票数，刻画市场广度。
- 识别大盘/小盘、价值/成长、周期/防御等风格相对强弱。

#### 4.2.2 行业与主题

- 输出行业涨跌幅、成交活跃度、资金变化和上涨家数占比排名。
- 识别连续走强、首次异动、冲高回落和连续走弱的行业。
- 归纳热点主题及代表股票，并关联支持该结论的新闻或公告。
- 区分事实数据与 Agent 推断；推断需标注置信度。

#### 4.2.3 市场状态判断

- 根据趋势、波动率、市场广度、流动性和风险事件，将市场标记为如“趋势上行、震荡、风险收缩”等状态。
- 给出状态判定所依据的指标，而非仅输出自然语言结论。
- 市场状态用于调整候选数量、因子权重和风险阈值。

#### 4.2.4 当日重要事件

- 汇总宏观、政策、行业及公司层面的重大事件。
- 每条事件包括发布时间、来源、涉及标的、可能影响方向和不确定性。
- 相同事件应聚类去重；可信来源优先，未经证实消息必须显著标注或排除。

### 4.3 次日选股

#### 4.3.1 股票池与硬性过滤

- 默认范围为当日正常交易的沪深 A 股。
- 可配置排除 ST/*ST、退市整理、上市未满 N 日、停牌、流动性不足的股票。
- 可配置排除次日预计无法正常交易或受涨跌停约束严重的股票。
- 对财务异常、重大监管风险、近期大额解禁等风险设置过滤或扣分规则。

#### 4.3.2 因子维度

- 趋势与动量：均线结构、区间收益、相对强度、突破情况。
- 量价与流动性：成交额、换手率、量比、放量持续性、价格冲击风险。
- 波动与风险：历史波动率、最大回撤、下行波动、跳空和尾部风险。
- 基本面质量：ROE、利润和营收增长、经营现金流、负债率。
- 估值：PE、PB、PEG、行业分位数；亏损企业采用适当替代指标。
- 行业与事件：行业强度、政策/公告催化、事件情绪与时效性。
- 市场适配：因子与当前市场状态的匹配程度。

#### 4.3.3 评分、排序与分散

- 各因子先按行业或全市场标准化，再按配置权重计算综合分。
- 输出原始指标、标准化分、权重、总分和排名，保证结果可解释。
- 限制单一行业候选数量，避免候选池过度集中。
- 默认输出 5～10 只重点候选和最多 20 只扩展观察标的，数量可配置。
- 当没有标的满足阈值时允许输出空候选，不得为凑数降低标准。

#### 4.3.4 单股卡片

每只候选股至少包含：

- 股票代码、名称、行业、收盘价、总分和置信度。
- 入选原因：建议 3 条以内，并引用对应数据或事件。
- 关键指标及其相对市场/行业分位。
- 主要风险与可能导致逻辑失效的条件。
- 次日观察条件，例如价格区间、成交确认或事件确认；不表达保证收益。
- 数据截止时间、所用策略版本和信息来源。

### 4.4 持仓复盘（可配置增强功能）

- 用户可录入持仓、成本、数量和自定义标签；敏感数据应加密并最小化存储。
- 分析持仓收益、行业暴露、个股集中度、相关性与组合回撤。
- 将持仓与候选池及风险事件交叉检查，输出观察提示。
- 未经明确授权不得连接券商账户或执行交易。

### 4.5 报告、查询与通知

- 生成 Markdown/HTML 报告，并支持后续扩展为 PDF。
- 报告结构：执行摘要、市场概览、行业热点、重要事件、市场状态、候选股、风险提示、数据质量说明。
- 提供按日期查看历史报告、候选股票和策略版本的能力。
- 支持在任务成功、降级或失败时通过配置渠道通知用户。
- 通知中只展示摘要和报告入口，避免泄露完整持仓等敏感信息。

### 4.6 反馈与效果跟踪

- 用户可对候选标记“有用、无用、加入观察、忽略”并填写原因。
- 自动计算候选股次日开盘、收盘以及 1/3/5/10/20 日表现。
- 同时统计相对基准和相对行业的超额收益。
- 跟踪命中率、平均收益、盈亏比、最大回撤、换手率、覆盖率和候选集中度。
- 明确绩效统计不等于可实盘收益，模拟交易应计入手续费、滑点和涨跌停限制。

### 4.7 策略配置与版本管理

- 管理股票池、过滤规则、因子、权重、阈值、候选数量和基准指数。
- 策略配置变更必须生成新版本，历史结果继续关联原版本。
- 支持启用、停用、复制、回滚和比较策略版本。
- 生产策略上线前应通过回测、样本外验证和人工审批。

## 5. 多角色 Agent 系统

系统应支持由多个专业角色协同完成复盘和选股。角色是具有明确职责、工具权限、输入输出格式和评价标准的逻辑 Agent；同一模型可按不同角色配置运行，也可为关键角色配置不同模型。V1 默认采用“协调者统一编排、专业角色独立分析、风控角色强制复核、报告角色统一发布”的模式。

### 5.1 角色体系

#### 5.1.1 协调与编排 Agent（Coordinator）

- 接收每日任务，检查交易日、数据就绪状态、策略版本和用户配置。
- 将任务拆分并分派给各专业 Agent，维护任务依赖和超时控制。
- 汇总结构化结果，发现缺失、重复或冲突后发起重试或仲裁。
- 只负责编排和结果整合，不绕过风控规则直接推荐股票。
- 输出本次执行计划、子任务状态、异常清单和最终发布决定。

#### 5.1.2 市场分析 Agent（Market Analyst）

- 分析指数趋势、成交额、市场广度、波动率和风格轮动。
- 判断市场所处状态，并输出判定指标、阈值、置信度和替代解释。
- 给出整体风险偏好及次日股票池应采用的仓位/候选数量建议，但不直接决定买卖。

#### 5.1.3 行业与主题 Agent（Sector Analyst）

- 比较行业和主题的涨跌、相对强度、扩散度、成交持续性和拥挤度。
- 识别领涨、补涨、退潮及可能发生风格切换的板块。
- 输出重点行业、回避行业、代表股票及判断依据。

#### 5.1.4 基本面研究 Agent（Fundamental Analyst）

- 评估盈利质量、成长性、现金流、资产负债、估值及行业相对水平。
- 识别财务恶化、异常审计意见、业绩预告变化等风险。
- 对财报数据严格使用公告可见时间，避免使用当时尚未公开的数据。

#### 5.1.5 技术与量化 Agent（Quant Analyst）

- 计算趋势、动量、反转、量价、流动性、波动和相对强度因子。
- 执行规则化筛选、标准化、评分和排序，并返回可复算的因子明细。
- 数值必须由确定性程序计算，不得由大模型估算或补齐。

#### 5.1.6 新闻与事件 Agent（Event Analyst）

- 收集公告、政策、宏观、行业和公司新闻，并执行来源评级、聚类去重和时效判断。
- 提取事件主体、发布时间、影响方向、影响期限、可信度和潜在反转因素。
- 将传闻、事实和分析观点分开；不能确认的传闻不得作为核心入选依据。

#### 5.1.7 资金与情绪 Agent（Flow & Sentiment Analyst）

- 分析成交活跃度、融资融券、龙虎榜及其他合法可用的资金代理指标。
- 评估市场情绪、拥挤交易、分歧程度和短期过热风险。
- 当相关数据源不可用时应明确降级，不把缺失数据解释为中性信号。

#### 5.1.8 风险控制 Agent（Risk Officer）

- 对所有候选执行交易状态、流动性、波动、财务、监管、事件和集中度检查。
- 拥有否决候选和阻止报告发布的权限，但必须返回结构化规则编号和证据。
- 检查候选间行业集中度、相关性及极端行情下的共同风险。
- 不负责为了达到候选数量而寻找替代股票，避免降低风控独立性。

#### 5.1.9 反方审查 Agent（Devil's Advocate）

- 针对每只重点候选主动寻找不应入选的证据、相反情景和逻辑失效条件。
- 检查确认偏误、热点追涨、单一来源依赖、因果混淆和叙事与数据不一致。
- 输出反方结论、证据强度以及建议保留、降级为观察或剔除。

#### 5.1.10 组合与候选池 Agent（Portfolio Constructor）

- 在通过风控的股票中进行跨行业分散、相关性控制和候选数量优化。
- 根据市场状态和用户风险配置决定重点池与扩展观察池，而不是提供确定性仓位指令。
- 输出纳入、未纳入原因及候选池整体暴露特征。

#### 5.1.11 报告 Agent（Report Writer）

- 仅基于已验证的结构化结果生成统一报告，不新增未经证实的事实和数值。
- 合并重复观点，显式呈现专业角色之间尚未解决的分歧。
- 保证每项关键结论附带数据时点、来源、策略版本和置信度。

#### 5.1.12 评估 Agent（Evaluator）

- 在后续交易日回收候选表现，计算绝对和相对收益、回撤及稳定性指标。
- 分析各角色观点和因子对结果的实际贡献，识别持续性偏差。
- 只能提出策略调整建议，不能自动修改或发布生产策略。

### 5.2 角色配置能力

- 管理员可启用、停用、复制角色，并配置角色描述、模型、Prompt、工具、数据权限、超时和重试次数。
- 支持针对不同市场或策略创建角色组，例如短线组、基本面组和 ETF 组。
- 每个角色的输入字段、输出 JSON Schema、最大耗时和失败降级方案必须版本化。
- 支持串行、并行和条件执行；无依赖的分析角色可并行运行。
- 角色配置变更须经过测试和审批，不应直接覆盖正在执行的任务。

### 5.3 标准协作流程

1. 协调 Agent 创建运行实例并冻结数据快照、用户配置和策略版本。
2. 数据质检通过后，市场、行业、基本面、量化、事件、资金情绪 Agent 并行分析。
3. 协调 Agent 将结果交给候选池 Agent 形成初选列表。
4. 风控 Agent 和反方审查 Agent 独立复核初选列表。
5. 被否决标的直接剔除；存在可解释分歧的标的降级为观察或进入仲裁。
6. 组合 Agent 对剩余候选执行分散和暴露检查。
7. 报告 Agent 根据已审核数据生成报告，协调 Agent执行发布前完整性检查。
8. 评估 Agent 在后续日期持续更新结果，并形成策略与角色表现报告。

### 5.4 输入输出契约

所有角色返回统一信封结构，至少包含：

- `run_id`、`role_id`、`role_version`、`strategy_version`。
- `as_of_time`、`data_snapshot_id`、`started_at`、`completed_at`。
- `status`：成功、降级成功、失败、超时或被跳过。
- `conclusions`：结构化结论，不接受只有自然语言的不可解析输出。
- `evidence`：指标、规则编号、数据来源、事件链接及发布时间。
- `confidence`：统一为 0～1，并说明置信度计算或映射规则。
- `risks`、`assumptions`、`missing_data` 和 `disagreements`。
- `model_version`、`prompt_version`、`tool_calls` 和资源消耗信息。

候选股票相关结论还必须包含证券代码、观点方向、适用期限、触发条件、失效条件和角色建议。系统应在进入下一阶段前校验 Schema；无效输出不得静默参与综合评分。

### 5.5 共享记忆与上下文管理

- 短期运行上下文只保存本次任务冻结后的数据和中间产物。
- 长期记忆保存历史报告、策略表现、已验证事实和用户显式偏好，不保存模型臆测为事实。
- 角色之间通过结构化任务和共享证据库通信，避免无限转发整段对话导致上下文污染。
- 每条记忆包含来源、创建时间、有效期、可信度和可撤销标记。
- 用户可查看、纠正和删除其偏好与持仓相关记忆。

### 5.6 冲突、仲裁与共识

- 系统不得以简单多数票替代证据审查；风险硬规则始终优先。
- 对市场方向或个股结论的冲突，按数据新鲜度、来源可信度、角色专业范围和历史校准度加权。
- 无法消除的重大分歧必须在报告中并列展示，不强行生成单一观点。
- 风控否决只有管理员通过带审计记录的人工流程才能覆盖；默认不可由其他 Agent 覆盖。
- 同一标的若只有单一角色支持，默认不能进入重点候选池，除非策略明确允许且风险 Agent 通过。

### 5.7 权限与安全边界

- 每个角色按最小权限分配数据源和工具；报告角色不能修改策略，分析角色不能发送通知或执行交易。
- 外部新闻和网页内容视为不可信输入，不能指示 Agent 改变角色、调用未授权工具或泄露数据。
- 工具调用需使用允许清单，并记录调用者、参数摘要、时间、结果状态和成本。
- 任何涉及持仓读取、策略发布、数据导出或未来交易接口的操作均需独立授权。
- 角色异常循环、成本超限或连续失败时，协调 Agent 应触发熔断并降级或终止任务。

### 5.8 多角色系统的可观测性

- 展示角色执行拓扑、状态、耗时、重试、输入输出版本及失败原因。
- 统计各角色有效结论率、Schema 合格率、引用覆盖率、平均置信度和校准误差。
- 记录每只候选从提出、复核、否决到入池的完整决策链。
- 监控角色观点趋同异常，防止所有角色因共享同一叙事而失去独立审查价值。
- 统计每个角色与模型的 Token、调用次数、费用和任务耗时。

## 6. Agent 通用行为要求

- 先验证数据，再计算指标，最后生成自然语言解释。
- 数值计算由确定性代码完成；大模型不得自行编造数值。
- 每个关键结论应能追溯到指标、规则或带时间戳的来源。
- 数据不足、来源冲突或结论不稳健时，明确表达不确定性。
- Prompt、模型、工具调用、策略配置和最终输出均应保留版本与审计记录。
- 防范新闻正文中的提示注入：外部内容只能作为数据，不能改变系统规则或触发敏感操作。
- 模型故障时可降级生成模板化量化报告，避免整条任务链不可用。

## 7. 业务规则与风险控制

- 风险过滤优先级高于收益评分；触发硬风险规则的标的不得进入重点候选。
- 报告显著展示“仅供研究参考，不构成投资建议”的声明。
- 不以未公开信息、违规抓取数据或来源不明的小道消息生成推荐。
- 不对用户进行收益承诺，不诱导高频交易、杠杆或集中持仓。
- 若后续增加自动交易，必须作为独立阶段重新评审权限、合规、额度、人工确认、熔断和撤单机制。

## 8. 非功能需求

### 8.1 性能与时效

- 数据就绪后 15 分钟内完成基础复盘与选股，目标可按数据规模调整。
- 常规报告查询响应时间 P95 小于 2 秒。
- 批量计算应支持增量更新和并行执行，但必须保证结果确定性。

### 8.2 可用性与可靠性

- 月度计划任务成功率不低于 99%。
- 数据拉取、计算、报告生成和通知分别支持幂等重试。
- 单一外部新闻源失败时允许降级；核心行情缺失时应停止选股。
- 任务状态包括等待数据、运行中、成功、降级成功和失败。

### 8.3 安全与隐私

- API 密钥通过密钥管理系统或环境变量注入，不写入代码和日志。
- 用户身份、持仓与通知地址按最小权限访问，传输与存储加密。
- 管理端操作、策略发布和数据导出保留审计日志。
- 日志脱敏，禁止记录完整令牌、账号凭证和不必要的持仓明细。

### 8.4 可维护性与可观测性

- 模块解耦：数据层、特征层、策略层、Agent 编排层、报告层、通知层。
- 监控数据延迟、缺失率、任务耗时、失败率、模型费用和推荐漂移。
- 关键计算提供单元测试；策略结果提供固定数据集回归测试。
- 所有时间统一存储时区信息，展示时使用用户配置时区。

## 9. 建议系统架构

```text
交易日历/调度器
       |
数据采集 -> 原始数据层 -> 数据质检 -> 标准化数据/特征库
                                      |
                     市场分析引擎 + 选股/风控引擎
                                      |
                          Agent 编排与证据聚合
                                      |
                    报告存储 -> Web/API -> 通知渠道
                         |
                 历史评估、回测与策略管理
```

建议核心实体：`security`、`trading_calendar`、`daily_quote`、`fundamental_snapshot`、`event`、`data_snapshot`、`dataset_manifest`、`feature_snapshot`、`strategy_version`、`screening_run`、`agent_run`、`candidate`、`risk_decision`、`report`、`portfolio`、`evaluation`、`audit_log`。

建议采用分层存储：

- 原始层（Raw）：保存外部数据的不可变落盘副本。
- 标准层（Normalized）：统一代码、交易日、字段类型、复权和行业口径。
- 特征层（Feature）：保存每日市场与个股特征快照，供选股和回测复用。
- 决策层（Decision）：保存多角色结论、候选评分、风控记录和策略版本。
- 展示层（Serving）：保存报告、查询索引和面向应用的聚合数据。

## 10. 任务编排与异常处理

### 10.1 每日任务

1. 判断是否为交易日并等待核心数据就绪。
2. 拉取行情、主数据、基本面与事件，写入原始层并生成数据清单。
3. 校验并发布标准数据，冻结 `data_snapshot_id`，计算和落盘市场及个股特征快照。
4. 生成市场复盘与状态标签。
5. 执行硬过滤、评分、风险检查和行业分散。
6. 生成报告并运行一致性检查。
7. 原子发布决策结果和报告，发送通知并记录运行指标。
8. 对上一批候选更新表现标签。

### 10.2 异常策略

- 核心行情覆盖率低于阈值：终止选股，发送失败通知。
- 非核心数据缺失：降级运行，并在报告顶部列出影响。
- 模型不可用：生成模板化报告，不影响量化计算结果入库。
- 重复触发：使用交易日、市场和策略版本组成幂等键。
- 报告中的数值与特征库不一致：一致性校验失败，不发布报告。
- 数据文件写入、校验或快照发布失败：禁止进入依赖该数据的后续阶段，并保留暂存区诊断信息。

## 11. 验收标准

### 11.1 数据与调度

- 给定交易日，系统能在配置时间自动启动且非交易日不生成日常选股。
- 核心行情数据完整率达到配置阈值，缺失时按规则中止或降级。
- 任一报告均可查看数据截止时间、数据源和策略版本。
- 每个交易日均产生可检索的原始、标准、特征和决策数据快照及完整 manifest。
- 对同一交易日补数或重跑不会覆盖旧版本，历史报告仍引用原始快照。
- 模拟写入中断时，未完成快照不会被查询或选股任务读取。
- 从指定 `data_snapshot_id` 重放策略时，确定性指标和候选评分与原运行一致。
- 备份恢复演练能在约定 RPO/RTO 内恢复快照、报告及其引用关系。

### 11.2 复盘报告

- 报告包含指数、成交、市场广度、行业表现、重要事件和市场状态。
- 随机抽查的关键数值均可与底层数据复算一致。
- 事实、规则结论和模型推断在展示上可区分。

### 11.3 选股结果

- 所有候选均通过配置的交易状态、上市时长、风险与流动性过滤。
- 每个候选展示总分、核心因子、入选原因、风险和数据时点。
- 相同数据和相同策略版本重复执行，候选和评分结果一致。
- 没有合格标的时系统正确输出空候选，并解释原因。

### 11.4 回测与审计

- 回测使用当时可得数据，并纳入复权、停牌、涨跌停、滑点和手续费规则。
- 可从任一历史候选追溯至输入快照、策略版本、计算记录与报告。
- 策略变更不会覆盖历史结果。

### 11.5 多角色 Agent

- 可通过配置启停角色，且配置变化形成新版本，不影响历史运行结果。
- 给定同一数据快照和角色版本，确定性计算结果一致，模型分析差异被记录。
- 无依赖的专业角色可并行执行；任一角色超时均按配置重试、降级或终止。
- 每个角色输出均通过 Schema 校验，并能追溯到输入快照、证据、模型和 Prompt 版本。
- 风控 Agent 能否决不满足硬规则的候选，其他 Agent 不能绕过其否决。
- 对重大分歧，报告能展示正反观点、支持证据、置信度和最终处置。
- 任一重点候选均可查看完整决策链，包括提出者、支持者、反方意见、风控结果和入池原因。
- 在新闻中注入工具调用或越权指令时，Agent 不执行该指令并记录安全事件。
- 当大模型不可用时，系统仍能保存量化结果并生成明确标记的降级报告。

## 12. 分阶段交付建议

### MVP

- A 股日线行情、交易日历、基础证券信息接入与质检。
- 指数/行业/市场广度复盘。
- 基于趋势、量价、波动、流动性的规则化选股及硬风险过滤。
- Markdown/HTML 报告、历史留存、任务日志和单一通知渠道。
- 候选股次日及多周期表现跟踪。
- 协调、市场、量化、风控和报告五个基础角色，以及结构化输入输出契约。

### V1

- 加入基本面、估值、公告与可靠新闻事件。
- 市场状态驱动的动态权重、策略管理、回测和样本外评估。
- Web 查询页、自选/持仓复盘、用户反馈和更完整的监控告警。
- 扩展行业、基本面、事件、反方审查、组合和评估角色，并提供角色配置管理页。

### V2

- 多市场、多策略组合、组合优化、情景分析和个性化风险预算。
- 在完成合规与安全专项评审后，再评估券商连接或人工确认式交易辅助。

## 13. 待确认事项

- 首期市场是否确定为 A 股，是否需要同时覆盖 ETF、港股或美股？
- 用户的投资周期是隔日、短线波段还是中长期？
- 偏好的风格、风险容忍度、最大候选数量和排除行业是什么？
- 可使用的数据源、授权范围、预算及更新时效分别是什么？
- 报告希望通过 Web、邮件、企业微信、钉钉或其他渠道发送？
- 是否需要导入持仓；若需要，采用手工导入还是只读券商接口？
- 选股评价基准、持有期和交易成本参数如何定义？
- 部署环境、用户规模、权限体系和数据保留期限是什么？
- 首期需要启用哪些角色，是否允许用户自定义新角色及 Prompt？
- 多角色之间更重视独立判断，还是允许共享其他角色的中间结论？
- 风控否决是否允许人工覆盖，覆盖需要哪些审批和审计信息？

## 14. 成功指标

- 任务成功率、按时出报告率和数据质量告警率。
- 用户阅读率、候选查看率、反馈率和持续使用率。
- 候选相对基准的多周期表现、最大回撤与稳定性。
- 策略样本内外差异、因子漂移和行业集中度。
- 单次任务耗时、模型成本及人工复盘节省时间。
- 角色输出合格率、证据引用率、冲突发现率、风险拦截率和置信度校准误差。

> 说明：收益类指标用于评价研究流程，不应作为产品对外承诺；上线决策应同时考察风险、稳定性、可解释性与数据质量。
